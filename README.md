# Hecate
> End-to-End чат на базе YubiKey.

**Hecate** — концепт десктопного чат-клиента, использующего аппаратный ключ YubiKey в качестве основы для end-to-end шифрования. Архитектура будет построена по принципу "нулевого знания" на сервере, где все сообщения и ключи чатов хранятся в зашифрованном виде. Доступ к данным возможен только при физическом наличии YubiKey, который хранит приватный ключ пользователя и выполняет все криптографические операции по расшифровке.

## For Developers

### Git Hooks & Workflow

Проект использует автоматизированную систему валидации коммитов и веток для поддержания качества кода:

**🎣 Git Hooks:**
- **commit-msg** — автоматически добавляет префикс к коммитам
- **pre-push** — валидация перед пушем

**🔄 GitHub Workflows:**
- **Branch Validation** — проверка формата веток
- **Commit Validation** — валидация истории коммитов в PR

### Установка хуков

```bash
./scripts/setup-hooks.sh
```

Скрипт предложит включить/выключить хуки и настроить логирование. 

💡 **Рекомендация:** Логирование чисто информативное — лучше выключить для чистого вывода.

### Правила именования

**Ветки:** `<category>/#<issue>/<description>`
```
frontend/#24/user-login
backend/#32/api-endpoint
junk/#15/experiment-feature
```

**Коммиты:** Просто опишите что сделано — префикс добавится автоматически (при условии, что ветка названа правильно)!
```
# Вы пишете:
add user login form

# Хук автоматически преобразует в:
frontend #24: add user login form
```

**Категории:** `frontend`, `backend`, `junk`

### Pull Request Policy

🔀 **Обязательно используйте Squash & Merge** для всех PR!

При мердже GitHub предложит название коммита — **обязательно исправьте его** на правильный формат:
```
# Неправильно (автоматическое название):
Add user authentication (#24)

# Правильно:
frontend #24: add user authentication
```

**Правила мерджа:**
- Только Squash & Merge (никаких merge commits!)
- Название коммита должно соответствовать формату: `<category> #<issue>: <description>`

## Криптографический глоссарий

### 1) ASN.1 - "схема данных"
- Абстрактный язык описания структуры (как JSON Schema, но для криптографии).
- Пример схемы ECDSA‑подписи: SEQUENCE { r INTEGER, s INTEGER }.
- Только описание, никаких байтов.

Короткий пример (понятия, не код):
```
ECDSASignature ::= SEQUENCE {
  r  INTEGER,
  s  INTEGER
}
```

### 2) DER - "байты по схеме ASN.1"
- Бинарная упаковка структуры по строгим правилам (Distinguished Encoding Rules).
- Любой объект (публичный ключ, сертификат, подпись) вначале существует как DER‑байты.

Пример: DER‑подпись ECDSA (r,s) закодирована в ASN.1 SEQUENCE и - это просто массив байтов. Часто его показывают в base64/base64url:
```
MEUCIQDo... (base64/base64url строки, сами байты не текст)
```

### 3) PEM - "текстовая обёртка вокруг DER"
- Это DER, закодированный в base64 и обрамлённый заголовками `-----BEGIN ...-----` / `-----END ...-----`.
- Нужен, чтобы удобно хранить и копировать текстом.

Пример PEM (тип Public Key):
```
-----BEGIN PUBLIC KEY-----
MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE0gVq3uVIx1l3m2mX3iVf8a5o7Dq7
H8q7U1n3x2Gqk5uQ3M8kXkqv6f0y4w6m1Q0oG1g4F1A6lq1J2vG2y3m0fQ==
-----END PUBLIC KEY-----
```

Важно: PEM - это не "формат ключа". Это оболочка. Содержимое PEM - это DER, а какой именно объект внутри - определяет следующее.

### 4) SPKI - "как описывается ПУБЛИЧНЫЙ ключ"
- SubjectPublicKeyInfo — ASN.1‑структура для публичного ключа.
- В PEM это всегда пара заголовков `BEGIN PUBLIC KEY` / `END PUBLIC KEY`.
- Внутри SPKI зашита информация об алгоритме (например, EC) и о параметрах (для P‑256 - OID `1.2.840.10045.3.1.7`).

Итого: "Публичный ключ в SPKI" = DER(SPKI) + (опционально) PEM‑обёртка.

### 5) PKCS#8 - "как описывается ПРИВАТНЫЙ ключ"
- Стандартная ASN.1‑структура для приватного ключа (под разные алгоритмы).
- В PEM это заголовки `BEGIN PRIVATE KEY` / `END PRIVATE KEY`.

Итого: "Приватный ключ в PKCS#8" = DER(PKCS#8) + PEM.

### 6) X.509 сертификат - "паспорт публичного ключа"
- ASN.1‑структура, которая содержит: публичный ключ (SPKI), данные субъекта/издателя, сроки, и подпись издателя.
- В PEM это `BEGIN CERTIFICATE` / `END CERTIFICATE`.

### 7) ES256 / ECDSA P‑256 + SHA‑256
- Алгоритм подписи: берём `SHA‑256(сообщение)` и подписываем приватным ключом P‑256.
- Подпись "в DER" - это ASN.1 SEQUENCE из двух чисел r и s (не r||s, а именно ASN.1).

Пример "как выглядит" DER‑подпись в тексте (показывают в base64url, без `=`):
```
MEUCIF1o0vQ1C1z8... (укорочено) ...IgYEA9u5-0lV7...
```

### 8) base64 vs base64url
- base64url - это base64, где `+` → `-`, `/` → `_`, паддинг `=` опускают.
- Мы используем base64url без `=` для challenge и для подписи (в API), чтобы удобно передавать в JSON/URL.

### 9) Challenge (челлендж)
- Сырые байты, которые нужно подписать. На сервере проверяется `ECDSA.Verify(SHA‑256(challenge), signatureDER)`.
- В API мы передаём challenge как base64url‑строку, а подпись - как DER в base64url.

### 10) "Attested" публичный ключ
- Публичный ключ, извлечённый из "аттестации слота" и заверенный аттестационным ключом устройства. 
- Это "истина" о том, какой ключ реально записан в слот сейчас. Сертификат в слоте может быть устаревшим, а attested - нет.

---

Карту соответствий для ключей запомнить просто:
- PUBLIC KEY ↔ SPKI (публичный)
- PRIVATE KEY ↔ PKCS#8 (приватный)
- CERTIFICATE ↔ X.509 (публичный ключ + "паспорт")
- PEM - лишь текстовая упаковка для любого из них (внутри - DER)
